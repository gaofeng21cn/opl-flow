## AntiGravity 执行进度与工具摘要规范
- **多步任务保持简短进度旁白**：连续调用多步工具的排查、开发或治理任务，在开干前、关键阶段切换以及执行有副作用的变更前，输出 1～2 句简洁进度说明（交代结论与下一步意图），避免长时间静默。
- **可读工具摘要**：填写 `toolSummary` 等任务摘要字段时使用简洁自然语言，便于折叠视图下快速识别当前步骤。

## AntiGravity 会话与 Prompt Cache 效率纪律
- **控制 Plan Mode 切换频率**：进出 Plan Mode 会改动系统前缀并直接击穿 Prompt Cache。简单或边界明确的改动不进入 Plan Mode；复杂方案只进入一次，定稿后一次性退出并连续执行，避免在实现阶段反复进出。
- **排障截图与长编码会话隔离**：不要在长编码会话（>150k tokens）中直接 `read_file` 图片，视觉检查统一委托独立 `research` 子代理返回纯文本结论。若用户贴图排障且当前会话已处于长上下文，主动提醒后续深度重构建议新开会话或执行 `/compact`，避免单张截图拖慢后续数百轮推理。
- **视觉/看图子代理同样短生命周期隔离**：带图质检子代理每次只审 1～3 帧即返回纯文本结论并结束，绝不让含图子代理滚成 >100k tokens 的长上下文。
- **长任务主动分段与压缩**：跨多阶段或上下文预计逼近 150k～200k tokens 时，在里程碑交接点主动提醒使用 `/compact` 或新开会话承接下一阶段，保持 Prompt Cache 命中率与低 TTFT。
- **Swarm 派活自带工具契约**：AntiGravity 不会向 Swarm Worker 挂载 MCP、用户 Rules 与 `SessionStart` 快照。调用 `swarm add` 派发编码或审计 Worker 时，Brief 必须同时写清：① 文件/模块所有权边界（并发写使用 `workspace: "share"`）；② `agy-fast --cli` 最小可执行命令样例（如已安装 `agy-fast`）；③ 明确验收命令与交付标准。
- **编排模式选型与共享文档防冲突**：多模块深度编码、探索与评审优先 `/teamwork`（继承 `agy-fast` MCP）；仅需独立 `worktree`/`share` 长时并行或异构模型分工时用 `/swarm`，并强制看板发帖 ≤15 行 / ≤1.5 KB；共享状态文件（如 `BRIEFING.md`/`progress.md`）按模块分片写入后由单一汇总者归并，避免并发 patch 失配。
- **非交互终端防卡死与单轮合并纪律**：不在 Agent 非交互终端中运行可能触发 `[y/n]` 或 `sudo` 密码提示的命令；发现后台任务无进展先查日志确认是否卡在交互提示并立即清理改走非交互路径（或交由用户在交互终端执行）；紧密耦合的验证/收尾步骤合并为单条自包含非交互命令执行。
- **本地优先验证再推送（Local-First CI）**：改动先在本地热缓存运行最窄必要验证修复后再 `git push`，不把 GitHub Actions 当远程调试循环，不在自托管与云端之间来回传输大体积构建缓存。
- **保持常驻上下文极简**：全局 `GEMINI.md` 只放跨项目通用纪律（远低于 24 KB 单文件上限）；项目事实放仓库 `AGENTS.md`，重复多步流程沉淀为按需加载的 Skill，低频外部集成避免常驻全局 `eager` MCP。

## Antigravity 与 Codex Supervisor 派活与分工原则
- **仅在用户明确要求时调用 Codex**：默认由 Antigravity 独立完成任务；仅当用户显式要求使用 Codex（如派活、监工、接管/分叉会话）时，才启用 `codex-supervisor`，不得在未点名时自行转包。
- **派活前必须先拆解，严禁盲目全盘转包**：即使用户明确要求派给 Codex，也只把 Codex 擅长的工程执行部分派出去，其余部分保留在 Antigravity 自己完成：
  - **留在 Antigravity 完成**：凡涉及理解/澄清用户意图、方案取舍与对外反馈的工作，包括文档类任务（PRD、设计文档、README、报告、Artifacts）、UI 视觉设计、交互逻辑设计与体验打磨，以及最终的面向用户汇报与验收结论。
  - **只派给 Codex 擅长的部分**：在意图、边界与验收标准明确后，将代码落地、重构、测试补全、本机电脑与终端操作（脚本/环境/服务排查）、构建打包与部署发布等执行任务派给 Codex。
- **接力与监工闭环**：复合任务按「Antigravity 对齐意图并完成文档/UI/交互设计 → 仅将代码落地、终端操作或部署子任务带明确 Brief 与验收命令派给 Codex → Antigravity 核查真实 diff/运行结果并向用户反馈」推进；若 Codex 执行中遇需求歧义或需改交互逻辑，由 Antigravity 拍板或向用户确认后 `steer` 纠偏，不让 Codex 自行揣测意图。
- **主动监督进度、超时止损拉回（绝不为了等待而等待）**：监工 Codex 时按任务复杂度设合理心跳与止损窗口（常规编码约 5～10 分钟心跳，重型构建/测试最长不超过 15～20 分钟，禁止盲等）。一旦进度明显慢于预期、长时间无实质推进或陷入环境/权限/测试死循环，先用 `status`/`history` 定位真实卡点并尝试一句 `steer` 纠偏；若纠偏无效、卡在需要强推理/交互判断的问题，或由 Antigravity 自己接手明显更快，果断 `interrupt` 止损并把已落盘改动拉回 Antigravity 直接收口，绝不为了等待而等待。
- **防过度派活与工具区分**：顺手几行能改完的小改动，或需与用户高频互动微调的 UI/文案，留在 Antigravity 就地完成；当前会话实时派活监工用 `codex-supervisor`，跨会话账本与多载体防双写走 `opl-flow`，无需 Codex 的内部多模块并行优先 `/teamwork`。
